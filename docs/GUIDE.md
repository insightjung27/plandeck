# PlanDeck 사용 가이드 (처음부터 따라하기)

코딩을 몰라도 **Claude Code에 커맨드를 순서대로 입력**하면 됩니다. 각 커맨드가 질문으로 안내하니 답만 하세요.
이 가이드는 "빈 프로젝트에서 완성된 화면설계서까지"를 손에 잡히게 따라가도록 썼습니다.

---

## 0. 준비 (한 번만)

1. 이 레포를 받습니다 — GitHub에서 **`Use this template`**(권장) 또는 `git clone`.
2. 받은 폴더에서 **Claude Code**를 엽니다(화면을 '저작'할 때 사용).
3. (미리보기) **`start.command`(맥)/`start.bat`(윈도)를 더블클릭** → 서버 실행 + 브라우저 자동 오픈.
   (터미널 선호 시 `python3 -m http.server 8137` → `http://localhost:8137/`)
   - 루트 `index.html` = **워크스페이스 홈**(프로젝트 목록). 처음엔 데모만 보입니다.

> **먼저 완성본 보기:** 워크스페이스에서 "간편결제 데모" 카드를 열면(= `projects/order-pay/index.html`)
> PRD→화면→예외→개발 인터페이스가 모두 동작합니다.

> PlanDeck는 한 저장소에서 **여러 프로젝트**를 운영합니다. 각 프로젝트는 `projects/<slug>/` 폴더입니다.

---

## 1. 프로젝트 시작 — `/pd-init`

```
/pd-init
```
묻는 것: **프로젝트 이름 · 한 줄 설명 · 서피스(단말)** — 모바일 / PC 웹 / 태블릿 / 키오스크 / 반응형(복수 선택 가능) ·
(선택) **전역규칙**(인증 방식·API 주소·에러 규약 — 모르면 비워두고 나중에).

→ `config/project.js` 와 `index.html` 이 생깁니다.

---

## 2. 상위 기획 — `/pd-prd` (정본 = `docs/PRD.md`)

```
/pd-prd
```
PRD의 **정본은 `projects/<slug>/docs/PRD.md`(마크다운 파일)** 입니다. `/pd-prd`가 이 파일을 만들거나 갱신합니다.
고정 7섹션(①배경 ②목표 ③사용자 ④범위+제외 ⑤성공지표 ⑥제약·가정·의존성 ⑦릴리스) + **요구사항·핵심 워크플로**를 담습니다.

- **업데이트 요청 시**: PlanDeck가 PRD.md를 읽어 그 내용으로 초안·디테일을 1차 생성합니다.
- **★역방향 보강**: PRD.md가 초안을 잡기에 부족하면, PlanDeck가 **부족한 부분을 역으로 질문**하고, 답을 받아
  **PRD.md를 새 버전으로 갱신**합니다. 충분해질 때까지 반복합니다.
- **버전 관리**: 변경·추가가 생기면 PRD.md 상단 `version`을 올리고 하단 **버전 이력**에 한 줄 남깁니다 — PRD.md는 계속 최신으로 유지됩니다.

> `config/prd.js`는 PRD.md에서 동기화되는 렌더용 미러입니다. `prd.html`을 열면 PRD가 보이고 **docs/PRD.md 원본**으로 이동할 수 있습니다.
> 팁: 워크플로는 "홈 → 상품상세 → 결제 → 완료"처럼 흐름으로, 분기는 "결제 성공/실패"처럼 적습니다.

---

## 3. 기본 화면 자동 생성 — `/pd-scaffold`

```
/pd-scaffold
```
PRD의 워크플로를 읽어 **기본 프로세스 화면 세트**를 만들어 기본 틀을 잡습니다.
중요 — **맵 선행**: 화면을 바로 만들지 않고, 먼저 **화면 인벤토리 + 플로우 + 가정/미결 질문**을 보여주고
**"이대로 만들까요?"** 를 묻습니다. 수정할 것을 말하면 맵을 고쳐 다시 보여줍니다. 승인하면 그제서야 빈 화면이 생깁니다.

→ `config/screens.js` 에 화면들이 추가되고, 각 화면 HTML이 생깁니다. `index.html` 에서 인벤토리를, 화면을 열면 플로우를 확인.

---

## 4. 디테일 기획 (화면별로 반복)

### 4-1. 화면 설계 — `/pd-wireframe [화면ID]`
대화로 **무엇이 있고(요소)·무슨 역할이며(기능)·어디로 이어지는지(흐름)** 를 정합니다.
무채색 **스켈레톤**이 그려지고, `components`(버튼·목록 등)와 `description`(기능 설명)이 채워집니다.
> 색·폰트 같은 디자인은 여기서 다루지 않습니다(그건 디자이너가 Figma에서).

### 4-2. 경우의 수 — `/pd-cases [화면ID]`
화면의 **모든 상태·예외**를 정합니다. 7종 상태(초기/로딩/정상/빈데이터/에러/권한없음/엣지)를 먼저 제시하니
각각의 동작·안내문구를 채우면 됩니다. CASES 패널(🧩)에 **커버리지 그리드**가 뜨고, **빠진 상태는 빨강**으로 보입니다.

### 4-3. 개발 인터페이스 — `/pd-interface [화면ID]` (★개발자 협업 단계)
이 화면이 필요로 하는 **API/데이터 계약**(reads/writes/events)을 정합니다. 데이터 구조는 `entities.js`에 한 번 정의하고
`{entities.Order}` 처럼 참조합니다. INTERFACE 패널(🔌)에서 확인하고, '계약 JSON 복사'로 개발자에게 바로 전달 가능.
> 이 단계는 **기획자 혼자가 아니라 개발자와 함께** 합니다 — 기획자는 '무엇을·왜'(의도·데이터·사용자 에러 문구),
> method/path/상태코드/멱등/페이지네이션 같은 **기술 계약은 개발자가 확정**. 혼자 추측해 넣지 마세요.

### 4-4. (디자이너) Figma 연결 — `/pd-figma-sync [화면ID] [figma url]`
디자이너가 Figma에서 완성한 시안을 화면에 **연결**합니다(designed:true). 실제 디자인은 Figma에서 합니다.

### 4-5. (QA) 수용기준 보강 — `/pd-qa [화면ID]`
QA가 예외·엣지 케이스를 함께 메우고 우선순위를 답니다. cases가 곧 테스트 케이스가 됩니다.

---

## 5. 점검 & 개발준비 — `/pd-lint`

```
/pd-lint
```
중복 ID·미연결 플로우·상태 커버리지 결손 등을 점검합니다. Description+Cases(100%)+Interface가 모두 있는 화면은
**개발준비(ready-for-dev)로 동결 승격**할 수 있습니다. 승격 후 스펙이 바뀌면 목록에 "변경됨"이 자동으로 뜹니다.

---

## 6. 핸드오프 — `/pd-handoff`

```
/pd-handoff
```
`handoff.html` 에서 전 화면 계약이 **OpenAPI 3.1 · 마크다운 스펙 · QA 테스트플랜(.feature) · 에이전트 번들**로
자동 생성됩니다. 버튼으로 내려받아 개발·QA에게 전달하거나, 배포 링크 자체를 "살아있는 핸드오프"로 공유합니다.

---

## 7. 확인 페이지 한눈에

| 페이지 | 누구를 위해 | 무엇 |
|---|---|---|
| `index.html` | 전원 | 프로젝트 개요 + 화면 인벤토리(상태·레이어) |
| 화면 HTML | 전원 | 프로토타입 + Description·CASES·INTERFACE·FLOW 패널 |
| `prd.html` | 전원 | PRD 전문 |
| `spec.html` | 팀·의사결정자 | 상세 기획서(화면별 전체 명세, 인쇄/공유) |
| `handoff.html` | 개발·QA | OpenAPI·스펙·테스트플랜·번들 |
| `?mode=review` | 의사결정자 | 검토 모드(기술 패널 숨김, 프로토타입만) |

## 자주 막히는 점
| 증상 | 해결 |
|---|---|
| 화면이 텅 빔 | 파일을 더블클릭하지 말고 **로컬 서버**로 여세요(상대경로 로딩). |
| 플로우 선이 없음 | 화면이 1개뿐이거나, flow.to(다음 이동)가 없음. 이동을 넣으면 그려집니다. |
| 점선 회색 노드 | 아직 안 만든 화면(유령). 그 화면을 만들면 자동 연결됩니다. |
| 커버리지 빨강셀 | 그 상태가 아직 미정의. `/pd-cases`로 채우거나 N/A로 명시하세요. |
| "변경됨" 배지 | 개발준비 승인 후 스펙이 바뀜 → 재검토 후 `/pd-lint`로 다시 승격. |
| hover 강조 안 됨 | 화면 루트가 `.pd-screen` 단일 래퍼인지, target `.pd-<역할>`이 실제로 있는지 확인. |
| 플로우/글꼴 안 뜸 | Mermaid·Pretendard는 인터넷(CDN) 필요. 폐쇄망이면 ARCHITECTURE의 vendoring 참고. |
