# 공통 컴포넌트 생성·관리 가이드

> **핵심: 컴포넌트는 프로젝트별이 아니라 PlanDeck 공용이다.** 한 번 만들어 모든 프로젝트가 가져다 쓰고, 변형·신규가 필요하면 **공용 라이브러리에 추가**해 전 프로젝트가 재사용한다. 각 프로젝트가 컴포넌트를 따로 만들지 않는다.

---

## 1. 어디서 관리하나 (SSOT 2파일)

| 역할 | 파일 | 내용 |
|---|---|---|
| **마크업 SSOT** | `engine/pd-components.js` | 컴포넌트 함수(= 구조). `C.row({...})`, `C.btn({...})` 처럼 호출해 조립 |
| **스타일 SSOT** | `engine/plandeck-ui.css` | 컴포넌트 CSS(= 디자인). `plandeck.css`가 `@import`로 로드 |

- `engine/*`는 **모든 프로젝트 공유**다. 프로젝트별 자체 컴포넌트/CSS 파일은 **없다**(두지 않는다).
- 컴포넌트 하나를 고치면 **그 컴포넌트를 쓰는 전 화면·전 프로젝트가 한꺼번에** 바뀐다.
- `components.html` = **살아있는 카탈로그**(현재 컴포넌트 미리보기). 4개 프로젝트가 같은 카탈로그를 본다.

**현재 공용 컴포넌트(21개, 6그룹)**: 네비게이션(appbar·apptop·tabbar·searchbar) · 리스트/카드(row·tiles·feature) · 배너/칩/상태(banner·chips·segment·doneState·emptyState) · 폼/버튼(field·textarea·check·toggle·btn·ctaBar·callBtn) · 콘텐츠(chatLog·bubble·legalDoc·heroBlock) · 관리자(kpi·table·wpanel).

---

## 2. 쓰는 법 (재사용 — 기본값)

- 화면은 공용 카탈로그에서 **가져다 조립**한다. 생성기(Node): `const C = require('engine/pd-components.js'); C.row({...})`. 브라우저: `window.PD.row({...})`.
- **인라인 스타일 금지**. 즉석 1회용 마크업 금지. (게이트가 0으로 강제 — `verify-render`)
- 모든 요소는 **정의된 공용 클래스를 최소 1개** 가져야 한다(그 클래스에서 스타일을 받음).

## 3. 변형이 필요할 때 (variant)

**기존 컴포넌트의 base를 고치지 않는다**(= 전 프로젝트에 영향). 대신 **modifier 클래스**를 additive로 추가한다.

```
<button class="pd-btn primary">기본</button>        ← 기존
<button class="pd-btn danger">삭제</button>          ← 변형: .danger 를 plandeck-ui.css에 추가(additive)
```

- base(`.pd-btn`)는 그대로, 변형은 **새 modifier 클래스**로만. → 타 프로젝트 무회귀.
- 추가 후 `verify-css`(베이스 충돌 0)로 안전 확인.

## 4. 신규 컴포넌트가 필요할 때

1. `engine/pd-components.js`에 **컴포넌트 함수**를 추가(파라미터 → 마크업). 고유 클래스명 사용.
2. `engine/plandeck-ui.css`에 **스타일**을 추가(`.pd-새이름` 또는 `.parent .child` 스코프 — 기존 클래스 덮어쓰기 금지).
3. 전 프로젝트에서 즉시 재사용 가능.
4. 게이트 통과: `verify-css`(충돌 0) · `verify-components`(즉석 0) · `verify-render`(인라인 0).

> **삭제 0 원칙**: 엔진은 공유이므로 **삭제·시그니처 변경 대신 additive**로만. 꼭 바꿔야 하면 전 프로젝트 영향을 먼저 검증.

## 5. 스타일 없는 '시맨틱 앵커'는 레지스트리에 등록

레이아웃 그룹/ JS 훅처럼 **의도적으로 스타일이 없는** `pd-*` 래퍼(예: 탭 패널 컨테이너)는 `tools/verify-components.js`의 **`HOOK_REGISTRY`에 등록**한다. 등록 = "이건 즉석 컴포넌트가 아니라 의도된 앵커"라는 선언.

- 레지스트리에 **없는** `pd-*` 클래스가 '정의 0개' 요소에 쓰이면 게이트가 **차단**한다 → 작성자가 (a)공용 컴포넌트를 쓰거나 (b)의도적으로 레지스트리에 등록하도록 강제.

## 6. 거버넌스 게이트 — 즉석 컴포넌트 유입 차단

```bash
node tools/verify-components.js <project>   # 정의0 + 미등록 pd-* 요소 = 즉석 컴포넌트 → 차단
node tools/verify-css.js                    # 베이스 클래스 충돌 0(변형이 base를 덮지 않았나)
node tools/verify-render.js  <project>      # 인라인 스타일 0
```

이 세 게이트가 "공용만 쓴다 / 변형은 additive / 즉석 금지"를 **눈이 아닌 결정론**으로 보증한다.

## 7. ⚠️ 공용 승격 후보 (현재 ad-hoc으로 반복 중)

아래 5개는 **여러 프로젝트에서 반복**되는데 아직 공용 컴포넌트로 정식 정의되지 않고 '스타일 없는 앵커'로 쓰이고 있다(현재 렌더는 정상). 반복 공용 패턴이므로 **정식 컴포넌트로 승격 권장**:

| 클래스 | 쓰는 프로젝트 | 추정 역할 |
|---|---|---|
| `pd-hero` | dodam · dodam-v1 · hulmate | 홈 상단 히어로 블록 |
| `pd-pagehead-actions` | dodam · dodam-v1 · hulmate | 페이지 헤더 액션 버튼 그룹 |
| `pd-tabpanels` | dodam · hulmate · order-pay | 탭 전환 패널 컨테이너(JS 훅) |
| `pd-kpi` | dodam-v1 · hulmate | 관리자 KPI 타일/행 |
| `pd-search` | dodam-v1 · order-pay | 검색 바 래퍼(공용 `searchbar`와 통합 검토) |

> 승격 = 현재 렌더를 바꾸지 않는 범위에서 `pd-components.js`+`plandeck-ui.css`에 정식 정의하고, HOOK_REGISTRY에서 제거. (J 요청 시 시각 회귀 검증과 함께 진행)

## 요약 — J가 할 일은 하나
**"이 컴포넌트에 OO 변형 필요" / "OO 컴포넌트 신규 필요"** 라고 말하면 → 공용 라이브러리(2파일)에 additive로 추가 → 전 프로젝트가 재사용. 각 프로젝트에서 따로 만들 필요 없음.
