📖 PlanDeck 활용 가이드

PlanDeck는 기획자가 주도해 클릭 가능한 화면설계서(프로토타입)를 만들고, 디자이너·개발자·QA·의사결정자가 각자 필요한 정보를 한곳에서 확인하는 기획 명세 단일 참조소(SSOT)입니다. Figma·IDE·테스트 러너를 대체하지 않고, 그들 사이의 "무엇을·어떻게 만들지"를 정본으로 잇습니다. 코딩을 몰라도 AI 코딩 도구에 지시(또는 자연어 요청)하면 됩니다.

0. PlanDeck이란 1. 최초 설정 2. 역할별 활용 3. 핵심 기능 4. 협업·배포 5. 커맨드 치트시트

0. PlanDeck이란 — 그리고 아닌 것

실제 서비스가 구현되는 것을 미리 염두하고 기획하는 도구입니다. 디자인·개발이 붙기 전에도 "어떤 내용이 어디에 배치되고, 눌렀을 때 화면이 어떻게 바뀌는지"를 실제로 시연합니다.

✅ 이런 도구입니다
PRD·화면·기능/버튼·경우의 수(예외)·개발 인터페이스(API/데이터 계약)·사용자 흐름을 담는 기획 명세 SSOT. 흑백 와이어프레임이 기본이고, 클릭하면 이동·탭/폼이 실제로 반응하는 프로토타입으로 시연합니다.
🚫 이런 도구는 아닙니다
Figma(픽셀 디자인)·IDE(코드)·테스트 러너(실행)를 대체하지 않습니다. 각 역할은 자기 전문 도구에서 '수행'하고, PlanDeck에서는 "무엇을 그/구현/테스트해야 하는지"를 확인·수령합니다.

1. 최초 설정 (처음 한 번)

약 3분, 코딩 불필요. AI 코딩 도구(Claude Code·Cursor·Antigravity·Orca 등)에서 진행합니다.

  1. 1
    내 저장소 만들기
    GitHub에서 이 템플릿을 “Use this template”로 복제(권장) 또는 git clone. 작업 규칙은 레포의 AGENTS.md가 어떤 AI 도구에서든 자동 적용됩니다.
  2. 2
    폴더를 AI 코딩 도구로 열기
    화면을 '저작'할 때 사용. Claude Code는 아래 /pd-* 커맨드를, 다른 도구는 같은 내용을 자연어로 요청.
  3. 3
    미리보기 띄우기
    start.command(맥)/start.bat(윈도) 더블클릭 → 서버 + 브라우저 자동 오픈. 루트 index.html이 워크스페이스 홈(프로젝트 목록)입니다.
  4. 4
    /pd-init — 새 프로젝트 생성
    이름·한 줄 설명·서피스(모바일/PC웹/태블릿/키오스크/반응형, 복수 가능)·버전을 물어봅니다. 답하면 projects/<이름>/ 폴더가 자동 생성되고 워크스페이스에 등록됩니다. 직접 폴더·파일을 만들 필요 없음.
먼저 완성본 보기: 워크스페이스에서 데모 카드(예: 간편결제·도담·훌메이트)를 열면 PRD→화면→예외→개발 인터페이스가 모두 동작합니다. 화면에서 탭·체크박스·입력·별점·수량·검색·FAQ를 눌러보세요 — 실제로 반응합니다.

2. 역할별 활용

핵심 원칙: 각 역할은 자기 업무를 각자의 전문 도구에서 수행하되, 그 업무에 필요한 정보는 모두 PlanDeck 한곳에서 확인합니다.

🧭기획자유일한 저작
상위 PRD → 디테일 기획 → 클릭 가능한 프로토타입으로 시연
  • 상위 기획: /pd-prd로 PRD(배경·목표·사용자·범위·지표·제약·릴리스 + 워크플로) 작성. 정본 = docs/PRD.md.
  • 기본 틀: /pd-scaffold로 화면 인벤토리+플로우를 '맵 선행'으로 펼치고 승인 후 생성.
  • 디테일: 화면별 /pd-wireframe(기능·버튼) → /pd-cases(예외) → /pd-interface.
  • 시연: 탭·폼·별점·수량·검색은 와이어에서도 실제 반응 → 의사결정자·팀과 "누르면 이렇게 바뀜"을 그대로 소통.
  • ★ /pd-interface는 개발자와 협업: 기획자는 '무엇을·왜'(의도·데이터·에러 문구), 기술 계약(method/path/멱등/인증)은 개발자가 확정.
🎨디자이너확인 → Figma
무엇을·어떤 상태까지 그려야 하는지 확인 후 Figma에서 디자인
  • 여기서 확인: 어떤 화면을, 어떤 구성요소(버튼·컴포넌트)로, 어떤 상태(로딩/빈데이터/에러/권한없음…)까지 디자인할지. 상태 커버리지 = "그려야 할 화면 변형 목록".
  • 컴포넌트 기준: 와이어는 공통 컴포넌트 라이브러리로 조립 → 디자인 시스템의 재사용 단위와 1:1로 맞춤.
  • 연결: Figma 완성 후 /pd-figma-sync <화면ID> <url>로 시안 연결(designed:true).
  • PlanDeck에서 픽셀을 그리지 않음 — "무엇을 그려야 하는지"를 빠짐없이 확인할 뿐.
💻개발자확인 → IDE
API/데이터 계약·분기·흐름 확인 후 IDE에서 구현
  • 여기서 확인: INTERFACE 패널(🔌) 화면별 API/데이터 계약(reads/writes/events·엔티티·에러·인증·멱등), CASES 패널(🧩) 분기/예외, 플로우에서 '버튼→API→다음 화면'.
  • 받아가기: /pd-handoff(handoff.html)에서 OpenAPI 3.1 JSON(mock·SDK)·마크다운 스펙·에이전트 번들 다운로드.
  • 추적성: 화면 ID(예: SCR-PAY-001)를 브랜치·커밋·PR에 넣어 기획↔구현 연결.
🧪QA확인 → 러너
수용기준·상태 커버리지 확인 후 테스트 러너에서 검증
  • 여기서 확인: 화면별 수용기준(Given-When-Then), 상태 커버리지(빠진 상태=빨강셀), 입력검증(EP/BVA).
  • 보강: /pd-qa로 기획자가 놓친 엣지·적대 입력·조합 케이스를 메우고 우선순위(P0~P2)·testId 부여.
  • 받아가기: /pd-handoff의 QA 테스트플랜(.feature + 체크리스트) 다운로드.
  • 클릭 가능한 프로토타입으로 흐름·경우의 수를 눈으로 사전 검증(shift-left).
👁의사결정자검토 모드
설치·계정 없이 브라우저로 프로토타입 확인·결재
  • 배포 링크(GitHub Pages)를 받아 브라우저로 열기 — 설치·계정 불필요.
  • 검토 모드(우측 상단 👁 또는 ?mode=review): 기술 패널 숨기고 화면+플로우 프로토타입만 깔끔히.
  • 플로우/목록을 클릭하며 사용자 여정을 따라 둘러보고 spec.html로 근거 확인 후 결정.
🧭 기획자 (저작)→🎨 디자이너→💻 개발자→🧪 QA→👁 의사결정자
기획자만 '저작', 나머지는 PlanDeck에서 확인·수령하고 각자 도구에서 수행. 화면 ID가 모든 역할을 잇는 공통 키입니다.

3. 핵심 기능

정적 목업이 아니라 실제 서비스처럼 반응하는 프로토타입 + 명세 도구.

🖱️ 클릭 가능한 프로토타입
모든 버튼·행·탭·뒤로가기에 실제 이동. 탭 누르면 내용 전환, 체크박스·토글·입력(타이핑)·별점·수량(±)·검색·FAQ 아코디언이 실제로 반응.
📱 흑백 와이어 + 디바이스 프레임
모바일(아이폰 프레임)·PC웹·태블릿·키오스크. 공통 컴포넌트만 조립(인라인 금지). 내용이 길면 목업 안에서 왜곡 없이 스크롤.
🔀 경우의 수(cases)
화면별 상태(정상/로딩/빈데이터/에러/권한없음/중복충돌…) + 입력검증. 상태 커버리지 게이트로 누락을 빨강으로 표시.
🔌 개발 인터페이스 → 핸드오프
화면=슬라이스 계약 → 유효 OpenAPI 3.1 + 마크다운 + QA .feature + 에이전트 번들 방출(handoff.html).
🧭 사용자 플로우
여정을 플로우별 카드 필름스트립으로. 채널(서피스)별 필터. 화면이 많아져도 플로우 단위로 정리.
⎇ 버전(브랜치) · 👁 검토 모드
한 프로젝트의 여러 버전을 카드 하나로 묶어 전환. 검토 모드로 의사결정자에게 프로토타입만 깔끔히.
완료 전 자동 검증(게이트): 링크 무결성(깨진·빈·막다른 링크 0) · 렌더(스크롤컨테이너·압축 없음) · role↔DOM 정합 · CSS 충돌 0. node tools/verify-links.js <project> 등.

4. 협업 · 배포

git이 동기화 버스, GitHub Pages가 공유 배포입니다.

  • 공유: 커밋·푸시하면 GitHub Pages에 자동 반영 → 링크만 보내면 누구나 브라우저로 확인(의사결정자 결재).
  • 역할 레인: CODEOWNERS로 engine·커맨드·공유파일을 경로 단위로 잠금. 변경은 작은 PR로.
  • 엔진 변경: engine/*는 전 프로젝트 공유 → 삭제 0·무회귀(additive) 원칙.
  • 병렬 작업: 여러 에이전트가 worktree에서 동시 작업 가능 — 화면·파일 단위로 독립적이게.

5. 커맨드 치트시트

Claude Code는 아래 /pd-*를, Cursor·Antigravity·Orca 등은 같은 내용을 자연어로 요청(규칙은 AGENTS.md가 보장). 막히면 /pd — 지금 뭘 할지 안내.
