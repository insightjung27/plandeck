# /pd-scaffold — PRD에서 기본 프로세스 화면 자동 생성

`config/prd.js`를 읽어 **기본 프로세스 화면 세트**를 자동으로 깔아 "기본 틀"을 잡는다.
핵심 원칙(벤치마크: Sketchflow·Lovable Plan Mode): **맵 선행** — 픽셀 이전에 화면 인벤토리+플로우(제품맵)를
먼저 제시하고 **사람이 검토·승인한 뒤에야** 빈 화면·스텁을 생성한다.

`$1` = 특정 서피스만 생성하려면 서피스 key(예: mobile). 없으면 PRD의 모든 서피스.

## 절차

### 1) PRD 로드 & 전제 확인
- **정본 `docs/PRD.md`를 먼저 읽는다**(없으면 `config/prd.js`). `config/project.js`, `config/screens.js`도 읽는다.
- PRD에 워크플로/화면 전개가 **초안을 잡기에 부족하면**, 바로 생성하지 말고 **`/pd-prd`(갱신 모드)로 부족분을 역질문→PRD.md 갱신**하도록 안내(역방향 보강 루프). 충분해지면 진행.

### 2) 맵 생성 (아직 파일 안 만듦 — 계획만)
각 workflow의 `steps`를 화면 인벤토리 + 간선으로 전개한다:
- 각 step.screen(이름) → 화면 ID 부여: `SCR-<약어>-<3자리>`. ★**결정론**: 이름→약어 매핑을 명시 사전으로 PRD(또는 scaffold 출력)에 적어두고 재실행 시 같은 ID가 나오게 한다(AI 임의 약어 금지 — 추적성 보존). 같은 이름은 **한 화면으로 병합**(중복 생성 금지).
- 멀티서피스면 서피스별로 화면군을 만들되, 같은 프로세스는 ID 접미(예: `-M`/`-PC`)나 surface 필드로 구분.
- 간선: step 순서를 `flow.to:[{screen, via}]` 체인으로. 분기(branch) 보존. 마지막 step은 to 없음.
- 첫 step(출처 없는 화면)에 `entry:true` 부여(의도된 진입점).
- 각 화면에 `reqIds`(해당 requirement), `surface`, `context`(workflow/step에서 추론) 시드.

### 3) ★ 맵 리뷰 게이트 (사람 승인)
생성 **전에** 다음을 사람에게 보여주고 승인받는다:
- **화면 인벤토리 표**: ID · 이름 · 서피스 · 진입점 · 다음 이동
- **가정/미결 질문**: PRD의 `openQuestions` + scaffold가 발견한 추론(예: "결제수단 범위 미정", "역할 2개로 추정")
- ★ **누락되기 쉬운 화면 체크리스트**(워크플로엔 잘 안 적히지만 거의 필요한 것): 로그인/인증 · 빈데이터 전용 · 에러/오프라인 · 확인 모달 · 설정 · 온보딩 · 권한없음. 각 항목을 "이 프로세스에 필요한가?"로 물어 누락을 선제 포착(맵선행은 '워크플로 전사'일 뿐, 이 체크리스트로 구조 완결을 보강).
- "이대로 생성할까요? 수정할 항목이 있나요?" 를 묻는다. 수정 요청이 있으면 맵을 고쳐 다시 보여준다.
- 승인 전에는 파일을 만들지 않는다.

### 4) 생성 (승인 후)
- `config/screens.js`: 카테고리 그룹에 각 화면 page 객체 추가.
  - `status:'draft'`, `designed:false`, `description:[]`, `components:[]`
  - `cases`: **상태 매트릭스 스텁** — 7종 상태(초기/로딩/정상/빈데이터/에러/권한없음/엣지)를 빈 행으로 시드하거나,
    최소한 커버리지 그리드가 "미정의(빨강)"로 뜨도록 비워둔다(엔진이 결손을 빨강셀로 표시).
  - `interface`: `{ reads:[], writes:[], events:[] }` 빈 스텁.
  - `flow.to`: (2)에서 만든 간선.
- 각 화면 HTML: `templates/project/_screen.blank.html`을 복사해 `projects/<slug>/<href>`(소문자 파일명)로 저장, `{{SCREEN_NAME}}`·`{{SCREEN_ID}}`·`{{SCREEN_HREF}}` 치환.
- `config/prd.js`의 openQuestions는 유지(해소되면 비운다).

### 5) 안내
- 생성된 화면 수·서피스별 분포 요약. `index.html`을 열면 인벤토리가, 각 화면을 열면 플로우가 보인다고 안내.
- 다음 단계 파이프라인 안내: 화면별 **`/pd-wireframe` → `/pd-cases` → `/pd-interface`** 로 구체화.
- 미등록(유령) 노드가 있으면 "해당 화면을 /pd-screen 으로 추가하면 자동 연결" 안내.

## 주의
- **맵 승인 전 생성 금지**(리뷰 게이트 필수). 비결정적 재생성 금지 — 산출물은 config(결정론 소스)다.
- 간선은 flow.to에만(from 금지). 중복 ID/파일명 금지. 기존 화면은 덮어쓰지 말고 추가만.
- 레이아웃을 '무에서' 만들지 않는다 — 와이어프레임은 이후 /pd-wireframe 의 큐레이션 스켈레톤 팔레트로.
